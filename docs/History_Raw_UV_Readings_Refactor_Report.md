# History Raw UV Readings Refactor Report

## 1. Previous History Semantics
Previously, the History page displayed aggregated `ExposureSessions`. These were continuously updated windows of UV exposure designed to group the thousands of 10-second readings into meaningful blocks (e.g., a trip outside). The History table columns showed Session Start, Duration, and Session Average UV.

## 2. New History Semantics
The History page now acts as a pure, chronological log of raw instantaneous UV readings. Each row in the UI maps 1:1 with a row in the `uv_readings` database table. The table columns now display Date, Time, instantaneous UV Index, and Risk Level.

## 3. Raw Reading Endpoint
A new dedicated endpoint `GET /api/v1/readings/history` was created. This protects the existing session endpoint from disruption and provides a clean separation of concerns.

## 4. Authentication / Ownership
The new endpoint uses strict user authentication (`requireAuth` JWT), NOT device authentication. It queries the `Device` table to find all devices explicitly owned by the authenticated user and filters the `uv_readings` query to only include readings generated by those devices.

## 5. Multi-Device Handling
The new backend query automatically discovers all `deviceId`s belonging to the `userId`. If the user owns multiple devices, the raw history will safely return a combined chronological log of readings from all owned devices. (An optional `deviceIdFilter` is also supported for future use).

## 6. Pagination
Server-side pagination is fully implemented using PostgreSQL `LIMIT` (take) and `OFFSET` (skip). The default limit is 50 records per page (bounded maximum of 100). The frontend pagination controls continue to work flawlessly with the new endpoint.

## 7. Realtime Update
The frontend continues to rely on Socket.IO (`exposure:updated`) invalidation. When a new reading arrives, the current page silently refetches in the background, making the newest reading instantly appear at the top of Page 1 without a hard refresh.

## 8. Offline Queue Behavior
Offline sync behavior natively maps to this new History design. When an ESP8266 reconnects and bulk uploads offline readings, the database persists them with their actual `recordedAt` timestamps. Because the History endpoint simply `ORDER BY recordedAt DESC`, these backfilled readings will automatically interleave correctly in chronological order, accurately reflecting the offline period.

## 9. ExposureSession Preservation
`ExposureLogicService` and the `exposure_sessions` table were untouched. Analytics, doses, and future alerts will continue to use the compressed session data. ONLY the History page UI changed data sources.

## 10. History Summary Cards
The summary cards at the top of the History page were updated:
- **Total Logs**: Now reflects total raw readings.
- **Page High UV Events**: Recalculated locally against the raw readings on the current page.
- **Page Average UV**: Averaged across the instantaneous readings on the current page.

## 11. CSV Export
The CSV export utility (`src/utils/history.ts`) was updated. It now exports `Date,Time,UV Index,Level` reflecting the instantaneous logs instead of the session summaries.
